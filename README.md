# Blip-Blop-for-Android
Blip &amp;  Blop port android

Blip & Blop is a game released in 2002 by LOADED Studio on Windows, developped in C++ and DirectX.  
After playing this game for a long time in my early teenage years, I later had the opportunity to see the [modernized source code](https://github.com/benkaraban/blip-blop) of the game (already using a partial port SDL) and I decided to port it on Android, it took about a week.
The compiled portage is available here : https://www.youtube.com/watch?v=mWfp6GL_Hqk

Update 2021 : 
This game is not available on Google play anymore, but a binary can be found on Amazon : https://www.amazon.fr/Smartties-Blip-Blop/dp/B00L1I5JPG/

## About this fork

This fork brings the 2014 port up to date so it builds with current Android
tools and runs on current phones and on Android TV, including the
**NVIDIA Shield**, where you only have a remote or a gamepad and no touchscreen.

### What changed

- **Build:** Gradle (Android Gradle Plugin 8.7, Gradle 8.10 wrapper) replaces
  ant. It uses NDK r27 and libc++, targets API 35 (minimum 21), and builds for
  armeabi-v7a, arm64-v8a and x86_64. The libraries support 16 KB memory pages.
- **Libraries:** SDL 2.32.10 and SDL_mixer 2.8.2 replace SDL 2.0.2. The
  game's Ogg Vorbis and MP3 music plays again.
- **64-bit fixes:** image decoding, the pause-menu darkening and the hi-score
  file used `long`, which is 8 bytes on arm64 and overran memory. These now use
  32-bit types. Stubs that were missing a return value now return one.
- **Android TV / Shield:**
  - The game appears in the TV launcher, with a banner.
  - Touchscreen, gamepad and leanback are all declared optional, so one APK
    covers phones and TVs.
  - Connecting or disconnecting a controller or remote no longer restarts the
    game.
- **Gamepad and remote:**
  - Every menu works with a TV remote (D-pad, OK and BACK). The PC game's
    OPTIONS screen does not exist on Android, so it is not in the menus.
  - The game can be played with any game controller (Shield, Xbox,
    PlayStation...).
  - Controllers can be connected or disconnected at any time. Disconnecting
    one during a level pauses the game.
  - **2-player mode** works when two controllers are connected ("START 2
    PLAYERS GAME").
  - BACK opens the pause menu instead of closing the app.
- **Display:**
  - The game runs full screen, without the status and navigation bars.
  - The 640x480 picture keeps its 4:3 shape at any resolution, with black
    bars on the sides (720p, 1080p, 4K, 20:9 phones).
  - It is scaled to the next whole multiple with sharp pixels, then smoothed
    down to fit the screen, so the pixels stay even without looking blurry.
- **Touch:**
  - The on-screen controls (stick, fire, jump, cow bomb, pause) exist now:
    `assets/ui/`, generated by `tools/make_touch_ui.py`.
  - They show only on touch devices, and hide when a controller is connected.
- **Gameplay:** the number of lives each player starts with is set in the
  main menu (**LIVES**, 3 to 99, default 10 instead of the original 5).
  Select it, press OK, change it with LEFT / RIGHT (UP / DOWN: by 10) and
  press OK to set it; on a touch screen, tap the left or right part of the
  line and then its middle. The choice is saved. Lives still carry over
  between levels; bonus stages still play with a single life and give the
  count back afterwards.
- **Lifecycle and saves:**
  - Leaving the app pauses the music and opens the pause menu.
  - Coming back resumes cleanly.
  - Hi-scores are saved to the app's internal storage.
  - EXIT in the menu closes the app properly.

## Building

You need the Android SDK with NDK 27.2.12479018 and JDK 17.

```sh
# 1. Game data (about 120 MB, not in this repository): copies data/ from
#    github.com/benkaraban/blip-blop into assets/data/
tools/fetch_game_data.sh

# 2. Build
export ANDROID_HOME=$HOME/Library/Android/sdk     # or your SDK location
./gradlew assembleDebug
```

The APK is written to `build/outputs/apk/debug/BlipBlop-debug.apk`. The build
stops with an error if `assets/data/` is missing.

For a release build, put your keystore in `keystore.properties` (not in git):

```properties
storeFile=/path/to/release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

or set `BLIPBLOP_STORE_FILE`, `BLIPBLOP_STORE_PASSWORD`, `BLIPBLOP_KEY_ALIAS`
and `BLIPBLOP_KEY_PASSWORD`, then run `./gradlew assembleRelease`
(`build/outputs/apk/release/`). Without a keystore the release APK is signed
with the debug key, which is enough for sideloading.

## Installing on an NVIDIA Shield (or any Android TV)

1. On the Shield, open **Settings > Device Preferences > About** and select
   **Build** 7 times to enable developer options.
2. In **Settings > Device Preferences > Developer options**, turn on
   **Network debugging** (called **ADB debugging** on some versions). The
   screen shows the Shield's IP address.
3. On your computer:

   ```sh
   adb connect <shield-ip>:5555        # accept the prompt on the TV
   adb install -r build/outputs/apk/debug/BlipBlop-debug.apk
   ```

4. "Blip Blop" now shows in the apps row of the TV home screen.

Phones: enable USB debugging, then run `adb install -r build/outputs/apk/debug/BlipBlop-debug.apk`.

## Controls

### Gamepad (Shield controller, Xbox, PlayStation...)

| Button                    | In game                   | In menus      |
|---------------------------|---------------------------|---------------|
| Left stick / D-pad        | Move, aim (8 directions)  | Move focus    |
| A (Cross)                 | Jump                      | OK            |
| X (Square), RB, RT        | Fire (hold)               | OK (X only)   |
| B (Circle), Y, LB, LT     | Cow bomb (special)        | Back (B only) |
| START                     | Pause menu                | OK / resume   |
| BACK / SELECT             | Pause menu                | Back          |

The first controller plays player 1. In a 2-player game the second
controller plays player 2 (see [Two players](#two-players)).

### TV remote (Shield remote, Android TV remotes)

| Remote key      | In game              | In menus    |
|-----------------|----------------------|-------------|
| D-pad           | Move, aim            | Move focus  |
| OK (center)     | Fire                 | OK          |
| Play/Pause, Menu| Jump                 | -           |
| Fast forward    | Cow bomb             | -           |
| BACK            | Pause menu / resume  | Back        |

Only the D-pad, OK and BACK are on every remote. Jumping needs a Play/Pause or
Menu key and the cow bomb needs a Fast forward key. Many remotes have no such
keys (the Google TV / Chromecast remote, the older Shield remotes), and many
can't send a D-pad direction and OK at the same time. On those remotes the
menus work but the game can't really be played. **A gamepad is recommended.**

Remotes and remote apps that send gamepad buttons (A, B, X, Y, START...)
without being a game controller work too: those buttons mean the same as on a
gamepad.

Screens that wait for a touch ("TOUCH TO BEGIN", intro, briefings, game
over) continue on OK, A, START or BACK.

### Keyboard

| Key                        | Action                      |
|----------------------------|-----------------------------|
| Arrows                     | Move, aim, menu focus       |
| Enter, Z, Ctrl             | Fire (Enter and Z: OK in menus) |
| X, Alt                     | Jump                        |
| C, Space                   | Cow bomb                    |
| Esc                        | Pause menu / back           |
| P                          | Pause menu                  |
| Backspace                  | Back (menus)                |

These keys always play player 1. In a 2-player game player 2 can also use
the keys of the PC game: Q, S, D, F (up, down, left, right), Tab (fire), G
(jump) and H (cow bomb).

### Touch (phones)

Drag anywhere on the left half of the screen for the virtual stick. The
buttons at the bottom right are fire, jump and cow bomb, and the button at the
top right is pause.

### Two players

1. Connect two game controllers (Bluetooth or USB). The first one to connect
   is player 1, the second one is player 2. A third controller is ignored
   until one of the two is disconnected, then it takes the free place.
   Outside a 2-player game, if player 1's controller is disconnected the
   other one becomes player 1.
2. Choose **START GAME > START 2 PLAYERS GAME**. With fewer than two
   controllers the game says "Connect two game controllers to play with two
   players" and stays in the menu.
3. On the character screen, player 1 picks Blip or Blop and player 2 gets the
   other one. Each player has a score / lives / ammo display: player 1 on
   the left, player 2 on the right.

Either controller moves through the menus and can pause or resume the game.
If a controller is disconnected during a level, the game pauses. Connect it
again (it gets its place back) and resume. When a player loses all lives,
the other one keeps playing until the game is over.

Two players need two controllers. The TV remote, the keyboard keys in the
table above and the touch controls always play player 1, so one controller
plus a remote or the touch screen is not enough for 2 players.
